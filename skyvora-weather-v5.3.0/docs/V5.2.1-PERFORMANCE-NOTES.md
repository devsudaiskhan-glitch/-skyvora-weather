# Skyvora Weather V5.2.2 — Performance Follow-up

## Evidence used

The supplied Chrome Performance trace (Responsive 400 × 847 viewport) showed a 188.8 ms full-document Layout with 1,270 dirty objects / 1,850 total objects, and a 203.7 ms module-evaluation event. The supplied Lighthouse dependency report showed approximately 24.5–24.7 seconds on forecast and air-quality requests.

## Changes

1. Forecast upstream requests now use one attempt with an 8-second timeout. Air-quality requests use one attempt with a 6-second timeout. Existing stale-cache fallback remains available. Other provider categories retain the existing general retry policy.
2. Browser API timeouts now end shortly after the backend forecast budget; air-quality has its own shorter client timeout.
3. Chart and notification modules are dynamically imported rather than included in the initial static module graph.
4. Below-the-fold dashboard sections use `content-visibility: auto` with an intrinsic-size estimate to reduce first-layout work without removing dashboard content.
5. The skip link has explicit keyboard focusability and a visible `:focus-visible` treatment.

## Verification status

Static tests, syntax checks and production asset audit are run for this package. This environment does not provide the user's exact Chrome Lighthouse device profile or live provider network, so no 95+ Lighthouse score is claimed. Run Lighthouse on the same computer, browser, viewport, location and throttling profile after installing this release.
